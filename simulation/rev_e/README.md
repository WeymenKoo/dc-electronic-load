# Rev E decks: the Rev C analog stage with the TLV9154

The same five circuits as `../01_dc_transfer` to `../06_cv_mode` (deck 05, thermal, has no op-amp and is not repeated), generated by the same
`tools/build_decks.py --rev-e` with three differences: the op-amps are TI's TLV9152 PSpice macromodel (`../lib/tlv915x.lib`, one amplifier,
shared by the TLV9154), the channel offset resistor Rb is 15M instead of 22M (+2.6 mV against the TLV9154's 0.83 mV Vos limit), and deck 03's
lowest current corner is 50 mA instead of 25 mA (25 mA per channel is now inside the dead zone). Everything else, including every `.meas`, is
identical so the two result sets compare line by line. The Rev C decks and their results are untouched.

```
rev_e/
├── 01_dc_transfer/      <name>.asc, <name>.plt, plot_<name>.py, README.md, results/ (reference .log and fig*.png)   exactly like the Rev C folders
├── 02_step_response/
├── 03_loop_gain/
├── 04_faults/
├── 06_cv_mode/
└── measurements_summary.txt
```

**Run them from a local copy.** LTspice (the CrossOver build) cannot write its `.raw` incrementally into a Google Drive File Stream folder
("Trouble writing ... to the disk"): `../tools/ltrun_local.sh rev_e/<deck>/<deck>.asc` mirrors the deck and `../lib` into `$TMPDIR/ltrun_local`,
runs LTspice there and copies `.log`, `.raw` and `.net` back. In the LTspice GUI, copy the `simulation` folder somewhere local first.
The TI macromodel is slow to find the operating point when every op-amp output sits at 0 V (dead zone): deck 01 takes about 13 minutes, deck 03
about 4; the "Direct Newton iteration failed" lines followed by "Pseudo Transient succeeded" are that fallback, not a failed run.

**What this means for the design.** Deck 06: the CV loop holds 1 A and 8 A sources exactly (the rail-to-rail output removes the LT1013's
0.25 % floor error), but at 0.1 A with 47 µF across the DUT it rings harder and longer than with the LT1013; 0.1 A stays the stated CV minimum
and a capacitive source at that current should be loaded in CC or given a few seconds.

 The IRFP250N (and the IRFP240 / IRF530 fallbacks) keep the Rev C margins with the 6× faster op-amp; the
3.3k / 1n / 47R compensation stays. The big-die IXTH proxy, which stands in for IXYS linear-rated parts that are not in the BOM, loses gain margin
and overshoots on hot-plug; if one is ever fitted, raise Cc to 2.2 nF and re-run decks 02 to 04. The 15M offset resistor moves the dead zone from
72 mA to 106 mA (the first 42 DAC codes); the firmware clamp (code ≥ 42 → 0 A) is the same mechanism as before.

Model-dependent numbers: the TLV9152 macromodel is TI's (SBOMB53B, 2021); treat rise times and margins as ±30 % and verify on the bench
(bring-up step 8 in `../../docs/rev_e_specification.md`).
